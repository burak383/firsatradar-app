## Bu surumde duzeltilen hatalar

FireVibe.ai ciktisi, derlemeyi engelleyen birkac hata iceriyordu. Hepsi
duzeltildi ve tum dosyalar gercek React Native/Expo tip tanimlarina karsi
`tsc` ile sifir hatayla type-check edildi:

  import ediyordu (`{ colors, fonts }`, `theme.colors`, default import).
  `theme.ts` artik hem `colors`/`fonts` (named), hem `theme` (named,
  `.colors`/`.fonts` iceren), hem de default export saglayarak ucunu de
  destekliyor.
- **KeFet.tsx:** Yanlis import yolu (`../theme` yerine `./theme` olmali
  -- tum dosyalar ayni klasorde).
- **Kategoriler.tsx:** Feather icon setinde olmayan 6 isim kullanilmisti
  (`bell-plus`, `scan-search`, `lamp-ceiling`, `shopping-basket`,
  `sparkles`, `dumbbell`) -- gecerli Feather karsiliklarina (`bell`,
  `search`, `home`, `shopping-cart`, `droplet`, `activity`) cevrildi.
  Ayrica `StyleSheet.absoluteFillObject` (artik yok) yerine
  `StyleSheet.absoluteFill` kullanildi.
- **Arama.tsx:** `MaterialCommunityIcons` setinde "amazon" ikonu yok;
  `FontAwesome` setine tasindi (RNDetay.tsx'te zaten dogru kullanilmisti).
  Ayrica `StatusBar`'in artik desteklemedigi `backgroundColor` prop'u
  kaldirildi (RN 0.76+ edge-to-edge Android'de bu prop kaldirildi).
- **Alarmlar.tsx:** Ayni `StatusBar backgroundColor` sorunu duzeltildi.
- **Profil.tsx:** `Icon`, `MarketplaceBadge`, `SectionHeading`, `BottomTab`
  bilesenlerinde tip tanimi yoktu; bu da bazi cagrilarda "eksik prop"
  hatalarina yol aciyordu. Tip tanimlari eklendi. Ayrica `styles` icinde
  `settingRow` iki kez tanimlanmisti (biri sessizce digerini eziyordu,
  satirlar arasi ayrac cizgisi kayboluyordu) -- tek, dogru tanima
  indirgendi.

## Backend'e baglanma

6 ekran artik statik/hardcoded veri yerine gercek bir REST API'den
besleniyor (`api.ts` -- fetch istemcisi). Backend `backend/` klasorunde:
Express + SQLite (better-sqlite3), ilk calistirmada ornek/demo verilerle
kendini doldurur (`seedIfEmpty()`), ayri bir kuruluma gerek yok.

### 1. Backend'i calistir

```bash
cd backend
npm install
npm start          # http://localhost:4000
```

Endpointler: `GET /api/deals`, `/api/deals/flash`, `/api/deals/featured`,
`/api/deals/:id`, `GET /api/categories`, `GET /api/search?q=`,
`GET/POST/PATCH/DELETE /api/alarms`. Detaylar icin `backend/routes/`.

### 2. Frontend'i backend'e isaret et

`api.ts`, `EXPO_PUBLIC_API_URL` ortam degiskenini okur, yoksa
`http://localhost:4000/api`'ye duser. Cihaz/emulator aginiza gore
degistirmeniz gerekebilir (bkz. `api.ts` basindaki not):

- Web / iOS simulator: `http://localhost:4000/api` (varsayilan, ekstra
  bir sey yapmaniza gerek yok)
- Android emulator: `EXPO_PUBLIC_API_URL=http://10.0.2.2:4000/api`
- Gercek cihaz (ayni Wi-Fi): `EXPO_PUBLIC_API_URL=http://<bilgisayar-ip>:4000/api`

### 3. Ek bagimlilik

`RNDetay.tsx`'teki kupon kodu kopyalama ozelligi icin:

```bash
npx expo install expo-clipboard
```

### 4. Hangi ekran neyi cekiyor

- **KeFet.tsx:** `getFlashDeal`, `getFeaturedDeal`, `getDeals` (indirime
  gore siralanmis liste), yemek kategorisinden bir firsat. Sureli firsat
  geri sayimi gercek `flashDealEndsAt`'ten hesaplaniyor.
- **RNDetay.tsx:** `getDealDetail` (fiyat gecmisi dahil), alarm
  olusturma/silme `createAlarm`/`deleteAlarm`, kupon kodu kopyalama.
- **Alarmlar.tsx:** `getAlarms` (ozet + liste), alarm ac/kapa ve silme
  optimistic update ile.
- **Kategoriler.tsx:** `getCategories` (kategori kutulari ve sayaclar),
  `getDeals({category:'elektronik'})` ve `getDeals({sort:'followers'})`
  (bu ikinci siralama backend'e bu oturumda eklendi -- bkz.
  `backend/routes/deals.js`).
- **Profil.tsx:** Sadece "Aktif takip" istatistigi `getAlarms` ozetinden
  geliyor; hesap/ayarlar kismi auth sistemi olmadigi icin kapsam disi
  birakildi.
- **Arama.tsx:** Arama kutusu `search(query)` cagirir; sonuc karti,
  magaza karsilastirma satirlari ve fiyat sinyali grafigi gercek
  `SearchResult` verisinden (primary + comparisons + priceHistory)
  olusturuluyor. Alarm butonu da RNDetay ile ayni create/delete akisini
  kullaniyor.

### 5. Telegram sinyallerini backend'e aktarma

`telegram_listener/` (ayri teslim edildi) ile yakalanan mesajlari bu
backend'e aktarmak icin:

```bash
cd backend
TELEGRAM_DB_PATH=/path/to/telegram_listener/data/messages.db \
  node import_telegram_signals.js
```

Script idempotent'tir (son islenen `raw_messages.id`'yi `import_state`
tablosunda tutar), yani periyodik/cron ile tekrar tekrar calistirilabilir
-- her calistirmada sadece yeni mesajlari isler ve fiyati degismemis
urunler icin gereksiz gecmis noktasi eklemez. `source='telegram'` olan
urunler dogrulanmamis fiyat SINYALLERIDIR, bkz. script basindaki not.
